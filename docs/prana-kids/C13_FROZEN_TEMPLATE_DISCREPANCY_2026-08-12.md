## 5. So what actually happened — the real explanation

**This is (b), but not a stale-runtime artifact like the T09 false alarm — it's a documentation/reporting gap.** The C13 check found these exact FAILs the very first time it ran, in the T03 pilot itself:

> `T03_REALIZATION_PILOT_2026-08-12.md` §4 (verbatim): *"Running it surfaced real findings, including in already-frozen T16/T21 (not part of this pass's scope, reported for awareness): 'Tara wanted to avoid getting into trouble.' recurs verbatim across 2 T16 situations, and 'Chinu checked anyway, like it might still happen after all.' recurs across 2 T21 situations. For T03 specifically, 'Tara tried again, a different way instead.' recurs across all 4 same-hero-name T03 situations sampled — this is `ctx.actionPhrases[1]` being pulled from a shared, apparently limited action-phrase pool, not a T03 architecture defect... a genuine, actionable finding... but out of scope here."*

So the T03/T16/T21 C13 FAILs were **known, documented, and correctly attributed to the shared `actionPhrases` pool** from the first day C13 existed. What happened afterward is a reporting artifact, not a code or data problem: every subsequent pilot report (T18, T14, T15, T04, T09) only ran and summarized C13 results **for its own newly-added cases** ("all 5 individually report C13: PASS," "all 4 natural cases... C13: PASS"). Each of those per-pilot claims is individually true. But their headline "Scope" lines (e.g. T18's "T03/T16/T21/T22/T23 (frozen/locked) untouched") got paraphrased in later summaries into "frozen templates: C13 PASS" — an inference nobody actually re-verified, because nobody re-ran the full merged audit and looked at T03/T16/T21's rows again after T03's own report first surfaced them. The full-corpus run (`runCorpusQualityAudit.js` with no filtering) has apparently never been re-summarized end-to-end since the T03 pilot — until `T09_SIT029_ROOT_CAUSE_2026-08-12.md` did it incidentally while re-running regressions for an unrelated question, and got flagged as a fresh "regression" that it isn't.

## 6. Connective-vs-mechanism classification of the 10 FAILs

Per the gap report's distinction (acceptable shared connective phrasing vs. mechanism-collapsing reuse):

- **"Tara tried again, a different way instead."** (T03 x4, T18 x1) — a bare connective/transition clause, no situation content, generated from a shared, limited `ctx.actionPhrases[1]` pool. This is scaffolding language, not two stories collapsing into the same mechanism — closer to "acceptable connective prose" than the SIT029-style bug, though it is still exactly the failure mode C13 was built to catch (shared literal sentence text), so C13 correctly flags it even though it's low-severity.
- **"Tara wanted to avoid getting into trouble."** (T16 x2) and **"Tara braced for anger, already deciding the mistake meant something bad about who Tara was."** (T16 x2) — these read as belief/setup sentences tied to a specific character framing, reused because SIT040/SIT060/SIT132 share the same `false belief` shape in T16's authored belief library, not a random connective. Milder than a full mechanism collapse but more content-bearing than the T03 case.
- **"Chinu checked anyway, like it might still happen after all."** (T21 x2) — similarly a belief/setup sentence tied to shared `false belief` text across SIT006/SIT120.

None of the 10 are the SIT029-style bug (a wrong *mechanism* being selected for the situation). All 10 are the shared-pool phrasing issue T03's report already named and scoped out.

## 7. Conclusion and recommendation

**Verdict: (b)-adjacent, specifically a reporting/summarization gap, not (a) changed logic, not (c) newly-exposed coverage, not (d) a code regression.** The C13 check itself is stable, has not drifted, and correctly reproduces the same 10 FAILs today that existed the day C13 was introduced. The situations flagged are the original pilot samples, not new ones. No pilot's edits touched another template's shared framing tables. The only thing that changed between "T03/T16/T21: C13 PASS" being stated in later summaries and today's fresh run is that nobody re-ran the unfiltered full audit and re-read the T03/T16/T21 rows after the first time — each subsequent report's PASS claim was accurate but scoped narrowly to its own new cases.

**Recommendation:** Do **not** revoke T03/T16/T21's frozen status on the basis of "regression" — there is none. But their "C13: PASS" characterization in downstream summaries should be corrected: they carry a known, low-severity, already-diagnosed C13 FAIL rooted in the shared `ctx.actionPhrases` pool (T03) and shared `false belief` library text (T16/T21), same root cause T03's own report named on day one. This is real content-quality debt worth fixing (tighten or diversify the shared action-phrase/belief pools for these specific situation clusters) but it does not require reopening the mode-detection/prose-contract work that was actually validated and frozen. Recommend: (1) fix the reporting gap immediately — any future "frozen template status" summary must re-run the full unfiltered `runCorpusQualityAudit.js`, not rely on a prior pilot's narrower per-template C13 excerpt; (2) file the shared-pool fix (action phrases for T03/T18, belief text for T16/T21) as its own small follow-up, separate from and lower-priority than the still-open 11-template Realization Contract rollout.
