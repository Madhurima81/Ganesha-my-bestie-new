# Phase 6A.12 - Story Structure Resolver

Version: 2.0
Status: LOCKED

## 1. Purpose

The Story Structure Resolver selects the narrative structure that best organizes the resolved story into a coherent journey.

The real source contract is:

```text
6A.11 Selected Logic Family
          ↓
storyStructures.hard.logic_family
          ↓
Candidate Structures
          ↓
Select Structure
          ↓
Carry forward:
  core_pattern
  scene_flow_template
```

This resolver determines the structural framework the story will follow.

It does not generate individual beats, prose, pages, openings, endings, symbols, or craft techniques.

## 2. Position in Engine

## 6. Responsibilities

The Story Structure Resolver must:

- Identify candidate Structures whose `hard.logic_family` matches the selected Logic Family.
- Select exactly one primary Story Structure.
- Carry forward the source-authored `core_pattern`.
- Carry forward the source-authored `scene_flow_template`.
- Record a deterministic selection trace when multiple Structures share the same Logic Family.
- Avoid inventing direct compatibility relationships that do not exist in the source data.

## 7. Workflow

```text
Read Logic
      ↓
Get Structures whose hard.logic_family matches the selected Logic
      ↓
Validate candidate Structure IDs
      ↓
If one candidate -> select it
      ↓
If multiple candidates -> deterministic tie-break
      ↓
Carry forward core_pattern + scene_flow_template
      ↓
Store Structure in Planner Context
```

## 8. Rules

SSR-001 Story Structure must exist in the approved Story Structure index.

SSR-002 Structure selection must be based on a real `hard.logic_family` match to the selected Logic Family.

SSR-003 Do not fabricate direct Structure compatibility claims involving Mission, Story Conflict, Adventure Archetype, Character, Belief Shift, or age.

SSR-004 Mission, Story Conflict, Adventure Archetype, Character, and Belief Shift may appear in explanation text as surrounding context, but not as source-backed hard filters.

SSR-005 Select exactly one primary Story Structure.

SSR-006 Do not invent Structure IDs. Real IDs are `STRUCT001`-style numbered IDs.

SSR-007 `core_pattern` and `scene_flow_template` are source data and must be preserved as such.

SSR-008 Do not generate individual story beats.

SSR-009 Do not determine page structure.

SSR-010 Do not determine prose.

## 9. Validation

Validate:

- Structure exists.
- Structure is active.
- Structure `hard.logic_family` matches the selected Logic.
- `core_pattern` is present.
- `scene_flow_template` is present.
- Exactly one primary Structure is selected.
- Resolution trace records whether selection was unique or tie-broken within the matched Logic Family set.

## 10. Failure Handling

If no compatible Structure exists:

- Return `STRUCTURE_UNRESOLVED`.
- Identify the failed compatibility relationship as missing `hard.logic_family` match coverage for the selected Logic.
- Do not randomly select a Structure.
- Do not modify upstream Logic to force compatibility.

If multiple Structures share the same Logic Family:

- Apply deterministic tie-break rules.
- Record the candidate set and the chosen winner.
- Do not pretend the choice was uniquely determined by source-backed Mission, Conflict, Archetype, Character, Belief, or age fields.
