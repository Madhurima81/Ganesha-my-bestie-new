# Phase 6A.14 - Opening Resolver

Version: 2.0
Status: LOCKED

## 1. Purpose

The Opening Resolver determines how the story should begin.

The real source contract is:

```text
openings.hard.opening_type
        ↓
storyTaxonomy.openingTypes[]
        ↓
Valid Opening Type
        ↓
Opening Strategy record
```

It selects a specific Opening Strategy using the real Opening Type contract, while treating Beat Plan, Character, Situation, Mission, and Story Structure as contextual guidance only.

It does not write the opening prose.

## 6. Responsibilities

The Opening Resolver must:

- Select an Opening Strategy whose `hard.opening_type` is valid against `storyTaxonomy.json` `openingTypes`.
- Use Beat Plan, Character, Situation, Mission, Story Structure, and Story Conflict as contextual guidance for choosing among valid Opening records.
- Preserve the source-authored Opening `description`.
- Preserve the source-authored `soft_suggested.purpose`.
- Introduce the protagonist and initial situation through the chosen Opening Strategy at the planning level, without claiming those are indexed compatibility fields.

## 7. Workflow

```text
Read candidate Opening records
      ↓
Validate each record's hard.opening_type against storyTaxonomy.openingTypes
      ↓
Use Beat Plan / Character / Situation / Mission / Story Structure as contextual guidance
      ↓
Rank valid Opening records
      ↓
Select Opening
      ↓
Preserve description + soft_suggested.purpose
      ↓
Store Opening Plan
```

## 8. Rules

OP-001 Opening must exist in the approved Opening index.

OP-002 Opening's `hard.opening_type` must be a valid `storyTaxonomy.openingTypes[]` ID.

OP-003 Do not invent a Beat-to-Opening mapping.

OP-004 Beat Plan, Character, Situation, Mission, Story Structure, and Story Conflict may guide selection contextually, but they are not direct Opening-index compatibility fields in the real source.

OP-005 Preserve source-authored `description` and `soft_suggested.purpose`.

OP-006 Opening must not reveal the complete resolution prematurely.

OP-007 Do not write prose.

OP-008 Do not determine page placement.

OP-009 Do not invent Opening IDs. Real IDs are `OPEN001`-style.

## 9. Validation

Validate:

- Opening strategy exists.
- Opening ID exists in `openingIndex`.
- `hard.opening_type` is a valid taxonomy entry.
- `description` is present.
- `soft_suggested.purpose` is preserved if present.
- Resolution trace distinguishes source-backed type validation from contextual guidance.

## 10. Failure Handling

If no compatible Opening exists:

- Return `OPENING_UNRESOLVED`.
- Identify whether the failure was invalid/missing `opening_type` coverage or selection deadlock among otherwise valid candidates.
- Do not invent an Opening Strategy.

If an Opening record's `hard.opening_type` is not found in `storyTaxonomy.openingTypes[]`:

- Exclude the record as an index/taxonomy integrity failure.
- Continue if other valid candidates remain.
