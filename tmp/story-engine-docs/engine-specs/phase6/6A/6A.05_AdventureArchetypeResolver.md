# Phase 6A.05 — Adventure Archetype Resolver

Version: 2.0
Status: LOCKED

## 1. Purpose

The Adventure Archetype Resolver selects the narrative adventure pattern that best expresses the protagonist's emotional journey.

**Resolution works at type level, not instance level, because that is what the source data actually supports:**

```text
Need + Character
      ↓
Candidate Mission Types (from Character.best_mission_types)
      ↓
Adventure Archetype (selected for compatibility with those Candidate Mission Types)
      ↓
compatible pools carried forward:
  Mission Types
  Logic Families
  World Types
  Obstacle Domains
  Story Actions
  Ending Types
```

**This resolver does not claim an Archetype → Need or Archetype → Character relationship.** No such field exists anywhere in `libraries/adventureArchetypes.json` — an Archetype record has no Need reference and no Character reference at all. Its only compatibility fields are `best_mission_types`, `best_logic_families`, `typical_ending_types`, `typical_world_types`, `typical_obstacle_domains`, `typical_story_actions`. `best_mission_types` is therefore the sole bridge connecting Archetype to everything upstream and downstream of it — Need and Character reach the Archetype only indirectly, through the Candidate Mission Types the Character's own `best_mission_types` field already supplies (Need's influence is already baked into Character selection at 6A.04 and is not re-applied here as a separate filter).

The resolver defines the type of journey the protagonist will experience and hands forward five compatibility pools that narrow later resolvers' searches. It does not select the specific Mission — that remains 6A.06, which further narrows within the Mission Types this resolver confirmed as viable.

## 2. Position in Engine

Character
      ↓
Derive Candidate Mission Types (Character.best_mission_types)
      ↓
6A.05 Adventure Archetype Resolver
      ↓
Adventure Archetype + compatibility pools
      ↓
6A.06 Mission Resolver (intersects Character.best_mission_types ∩ Archetype.best_mission_types for final Mission Type lock)

## 3. Inputs

From Planner Context:

- Core Need (context only — see §1; not used as a direct filter here)
- Character (specifically `character.soft_suggested.best_mission_types`, used to derive Candidate Mission Types)
- Belief Shift (context only, carried in trace; Archetype has no direct Belief field)
- Situation
- Target age

## 4. Outputs

- Adventure Archetype (selected)
- Candidate Mission Types (the intermediate set derived from Character, retained in trace)
- Compatibility pools carried forward for downstream resolvers:
  - `bestMissionTypes` → consumed by 6A.06 (Mission)
  - `bestLogicFamilies` → consumed by 6A.11 (Logic)
  - `typicalWorldTypes` → consumed by 6A.08 (World, matched against `world.hard.world_types`)
  - `typicalObstacleDomains` → consumed by 6A.09 (Obstacle, matched against `obstacle.hard.obstacle_domain`)
  - `typicalStoryActions` → consumed by 6A.07 (Story Action)
  - `typicalEndingTypes` → consumed by 6A.15 (Ending, matched against `ending.hard.ending_type`)
- Archetype resolution trace

## 5. Resources Used

- `plannerKnowledge.adventureArchetypeIndex` (source: `libraries/adventureArchetypes.json`)
- `plannerKnowledge.characterIndex` (for `best_mission_types`)
- Planner Rules

## 6. Responsibilities

- Derive the Candidate Mission Type set from the resolved Character's `best_mission_types`.
- Identify Archetypes whose own `best_mission_types` intersects that candidate set.
- Rank remaining Archetypes (e.g. by intersection size, or by any other locked tie-breaking rule — see §8).
- Select the best Archetype.
- Carry forward the selected Archetype's full compatibility bundle (`best_logic_families`, `typical_world_types`, `typical_obstacle_domains`, `typical_story_actions`, `typical_ending_types`) as candidate pools for the resolvers that will consume them later in the chain.
- Pass the resolved Archetype to the Mission Resolver.

## 7. Workflow

```text
Read Character.best_mission_types
      ↓
Set Candidate Mission Types = Character.best_mission_types
      ↓
Get Archetypes where Archetype.best_mission_types ∩ Candidate Mission Types ≠ ∅
      ↓
Remove Incompatible Archetypes (empty intersection)
      ↓
Rank
      ↓
Select Archetype
      ↓
Validate
      ↓
Store Archetype + compatibility pools in Planner Context
```

## 8. Rules

AR-001 Archetype must exist in the approved Archetype index.

AR-002 Archetype selection is driven by Mission Type compatibility (`best_mission_types` intersection with Character's Candidate Mission Types) — this is the primary and only direct compatibility check.

AR-003 Archetype must not be required to have a direct Need or Character compatibility field, because none exists in source data. Do not fabricate one.

AR-004 Archetype must be compatible with the Situation only insofar as the Situation's own downstream implications (Need, Character) already shaped the Candidate Mission Type set — no separate direct Situation check on the Archetype record itself.

AR-005 Archetype's compatibility pools (`best_logic_families`, `typical_world_types`, `typical_obstacle_domains`, `typical_story_actions`, `typical_ending_types`) must be carried forward verbatim into the Planner Context trace for downstream resolvers — 6A.05 does not resolve those downstream decisions itself, only narrows their candidate pools.

AR-006 Do not invent archetype IDs.

AR-007 Select one primary Adventure Archetype.

AR-008 If the Candidate Mission Type set is empty (Character has no `best_mission_types`), this is a data-integrity failure in the Character record, not an Archetype resolution failure — report accordingly (see §10).

AR-009 If multiple Archetypes have identical compatibility bundles (observed in real data — e.g. `ARCHETYPE_TREASURE_HUNT`, `ARCHETYPE_SECRET_DISCOVERY`, `ARCHETYPE_HIDDEN_WORLD` currently share one bundle), tie-break deterministically by lowest ID (lexicographic) unless a future rule set introduces richer differentiation.

## 9. Validation

Validate:

- Archetype exists.
- Archetype's `best_mission_types` intersects the Character-derived Candidate Mission Types.
- Compatibility pools are present and non-empty where the source record has them (some archetypes may legitimately have a sparse pool for one category — that is not itself a failure).
- Exactly one primary archetype is selected.

## 10. Failure Handling

If no Archetype's `best_mission_types` intersects the Candidate Mission Type set:

- Return ARCHETYPE_UNRESOLVED.
- Do not randomly select an archetype.
- Do not modify upstream Character or Need decisions to force compatibility.

If the Candidate Mission Type set itself is empty:

- Return ARCHETYPE_UNRESOLVED with reason `CHARACTER_HAS_NO_MISSION_TYPES` — distinct from a normal empty-intersection failure, since the root cause is upstream data, not this resolver's compatibility logic.
