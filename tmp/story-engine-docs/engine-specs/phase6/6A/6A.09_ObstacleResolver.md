# Phase 6A.09 — Obstacle Resolver

Version: 2.0
Status: LOCKED

## 1. Purpose

The Obstacle Resolver selects the primary obstacle that prevents the protagonist from easily completing the Mission.

**Primary bridge — the only hard, authoritative filter:**

```text
Archetype.typicalObstacleDomains
        ↓
Obstacle.hard.obstacle_domain
        ↓
Candidate Obstacles
```

**Mission, Character, World and Belief have no direct hard-field relationship to Obstacle at all.** None of `libraries/missions.json`, `libraries/characters.json`, `libraries/worlds.json`, or `ontology/beliefs.json` / `libraries/situations.json` contains any field referencing an Obstacle, an Obstacle Domain, an Obstacle Type, or an Obstacle Function. This resolver does not invent `compatibleMissionIds`, `compatibleCharacterIds`, `compatibleWorldIds`, or `compatibleBeliefIds` on the Obstacle index — none of those relationships exist in source data.

**What the Obstacle record itself does carry**, as advisory-only raw text (never resolved IDs):

- `soft_suggested.best_life_domains_raw: string[]` — raw Life Domain *names* (e.g. `"Exploring & Nature"`), matchable only against a Mission's own raw `bestLifeDomains` text field (also unresolved) — this is a raw-text-to-raw-text comparison, doubly soft, never a hard ID match.
- `soft_suggested.best_story_actions_raw: string[]` — raw Story Action *names* (e.g. `"Search"`), matchable only against a resolved Story Action's ID by name-similarity, not by ID.
- `soft_suggested.best_story_worlds_raw: string[]` — raw World *names* (e.g. `"Hidden Cave Network"`), matchable only against a resolved World's `name` field, not its ID.

**Authoritative classification vs. advisory evidence, preserved exactly:**

- `hard.obstacle_domain` / `hard.obstacle_type` / `hard.obstacle_function` — resolved, authoritative ontology classification. `obstacle_domain` is the field this resolver's primary filter uses.
- `soft_suggested.best_life_domains_raw` / `best_story_actions_raw` / `best_story_worlds_raw` — advisory, raw, unresolved text. Usable only as optional tie-break signals, never as a hard filter, and never silently "resolved" to IDs by name-matching without an explicit audited mapping step (same no-guessing principle locked for Mission Type and World's `best_adventure_archetypes_raw`).

## 2. Position in Engine

Adventure Archetype (`typicalObstacleDomains`)
      ↓
6A.09 Obstacle Resolver
      ↓
Obstacle
      ↓
6A.10 Story Conflict Resolver

Mission, Character, World, and Belief Shift pass through the Planner Context as informational context only — carried forward for trace/logging and for downstream resolvers, but they do not filter Obstacle selection, because no data field connects them to it.

## 3. Inputs

From Planner Context:

- Adventure Archetype (`typicalObstacleDomains`) — the sole hard-filter source
- Mission, Character, World, Belief Shift — context/trace only, not filters
- Situation
- Target age

## 4. Outputs

- Selected Obstacle
- Candidate Obstacle set (trace, before tie-breaking)
- Obstacle compatibility result, explicitly noting the hard filter used and any soft/raw tie-break applied
- Obstacle resolution trace

## 5. Resources Used

- `plannerKnowledge.obstacleIndex` (source: `libraries/obstacles.json`)
- `plannerKnowledge.adventureArchetypeIndex` (`typicalObstacleDomains`)
- Planner Rules

## 6. Responsibilities

- Build the Candidate Obstacle set: Obstacles whose `hard.obstacle_domain` appears in Archetype's `typicalObstacleDomains`.
- If more than one Candidate remains, apply optional soft/raw tie-breaking using `best_story_worlds_raw` (name match against the resolved World), `best_story_actions_raw` (name match against resolved Story Actions), or `best_life_domains_raw` (raw text match against Mission's own raw `bestLifeDomains` text) — always recording which soft signal, if any, was used.
- Select one primary Obstacle.
- Record `hard.obstacle_type` and `hard.obstacle_function` in the trace even though they aren't filter inputs here — they're needed by 6A.10 Story Conflict Resolver next.

## 7. Workflow

```text
Read Archetype.typicalObstacleDomains
      ↓
Get Candidate Obstacles where Obstacle.hard.obstacle_domain ∈ typicalObstacleDomains
      ↓
If multiple candidates:
      Attempt soft/raw tie-break (best_story_worlds_raw / best_story_actions_raw / best_life_domains_raw)
      ↓
Select Obstacle
      ↓
Validate
      ↓
Store Obstacle (with obstacle_domain, obstacle_type, obstacle_function) in Planner Context
```

## 8. Rules

OR-001 Obstacle must exist in the approved Obstacle index.

OR-002 The sole hard filter is `hard.obstacle_domain` ∈ Archetype's `typicalObstacleDomains`.

OR-003 Do not create or assume `compatibleMissionIds`, `compatibleCharacterIds`, `compatibleWorldIds`, or `compatibleBeliefIds` on the Obstacle index — none exist in source data.

OR-004 `best_life_domains_raw`, `best_story_actions_raw`, `best_story_worlds_raw` remain raw/soft evidence. They may inform tie-breaking only, and any such use must be recorded as a soft signal in the trace — never treated as a resolved-ID compatibility field.

OR-005 A raw-text-to-raw-text comparison (e.g. Obstacle's `best_life_domains_raw` against Mission's own raw `bestLifeDomains`) is doubly unresolved and must be flagged even more explicitly as low-confidence than a raw-to-resolved comparison (e.g. against a World's actual `name`).

OR-006 Obstacle must be age appropriate (Planner Rules general constraint — no per-Obstacle age field exists in source data).

OR-007 Do not invent Obstacle IDs.

OR-008 Select one primary obstacle.

## 9. Validation

Validate:

- Obstacle exists and is active.
- Selected Obstacle's `hard.obstacle_domain` is present in Archetype's `typicalObstacleDomains` (the one non-negotiable hard check).
- If a soft/raw tie-break was used, it is explicitly flagged in the trace as such, with the specific field and comparison type (raw-to-resolved vs. raw-to-raw) recorded.
- `hard.obstacle_type` and `hard.obstacle_function` are captured in the trace for 6A.10's use.

## 10. Failure Handling

If no Obstacle's `hard.obstacle_domain` appears in Archetype's `typicalObstacleDomains`:

- Return OBSTACLE_UNRESOLVED.
- Do not fall back to a soft/raw signal as a substitute hard filter.
- Do not randomly select an Obstacle.
- Do not modify upstream Archetype selection to force compatibility.

If multiple Candidates remain after the hard filter and no soft/raw tie-break produces a clear winner:

- Apply deterministic tie-breaking (lowest ID) as the final fallback, and record that no soft signal resolved the tie.

## 11. Deliverables

- Selected Obstacle (with `obstacle_domain`, `obstacle_type`, `obstacle_function`)
- Candidate Obstacle set (trace)
- Compatibility result (hard filter + any soft tie-break used)
- Obstacle resolution trace

## 12. Dependencies

Inputs

- Adventure Archetype (`typicalObstacleDomains`)
- `plannerKnowledge.obstacleIndex`
- `plannerKnowledge.adventureArchetypeIndex`

Next Module

- 6A.10 Story Conflict Resolver (consumes the Obstacle's `obstacle_type`/`obstacle_function`, not just `obstacle_domain`)

## 14. Example Input

```json
{
  "adventureArchetype": {
    "id": "ARCHETYPE_TREASURE_HUNT",
    "typicalObstacleDomains": ["OD_PUZZLE"]
  },
  "mission": {
    "id": "19",
    "bestLifeDomains": ["Exploring & Nature", "Playing & Games"]
  },
  "world": { "id": "WORLD015", "name": "Waterfall Caves" },
  "storyActions": [{ "id": "ACTION_SEARCH" }]
}
```

## 15. Example Output

```json
{
  "candidateObstacles": ["OBST046", "OBST047", "OBST048", "OBST049", "OBST050", "OBST051", "OBST052", "OBST053", "OBST054", "OBST055"],
  "obstacle": {
    "id": "OBST048",
    "name": "Locked Door",
    "hardObstacleDomain": "OD_PUZZLE",
    "hardObstacleType": "OT_EXTERNAL",
    "hardObstacleFunction": "OBSTACLE_BLOCKED_PATH",
    "reason": "Hard filter: obstacle_domain OD_PUZZLE matches Archetype.typicalObstacleDomains. Soft tie-break: best_life_domains_raw ['Exploring & Nature'] exactly matches Mission's own raw bestLifeDomains text (raw-to-raw, low confidence per OR-005); best_story_actions_raw ['Search'] name-matches resolved ACTION_SEARCH (raw-to-resolved); best_story_worlds_raw ['Hidden Cave Network'] references a different Candidate World (WORLD034) from 6A.08's candidate set, not the selected WORLD015 — noted as partial, non-decisive evidence."
  }
}
```

Note: the raw-text evidence in this example is genuinely mixed — some signals point toward the selected World, one points to a different Candidate World from the same 6A.08 candidate set. This is realistic and expected given the data is soft/advisory; it is reported honestly in the trace rather than cherry-picked to look cleaner than it is.
