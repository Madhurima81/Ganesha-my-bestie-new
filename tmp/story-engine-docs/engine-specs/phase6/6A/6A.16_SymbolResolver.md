# Phase 6A.16 - Symbol Resolver

Version: 2.0
Status: LOCKED

## 1. Purpose

The Symbol Resolver selects meaningful Ganesha Symbols that can reinforce the story's emotional and thematic journey.

The real source contract is:

```text
ganeshaSymbols.id
      ↓
symbol_theme
      ↓
symbolThemes[]
```

The real compatibility fields are limited to:

```text
Need
Mission Type
   ↓
Ganesha Symbol
```

Everything else - Belief, World, Beat Plan, Structure, Opening, Ending - is contextual guidance only.

Symbols must serve the story rather than function as decoration.

## 6. Responsibilities

The Symbol Resolver must:

- Identify Ganesha Symbols compatible with the resolved Need and Mission Type.
- Validate every selected symbol's `symbol_theme` against `symbolThemes.json`.
- Preserve `best_need_ids` and `best_mission_types` exactly as sourced.
- Use Belief, World, Beat Plan, Structure, Opening, and Ending as contextual guidance only.
- Avoid unnecessary symbolic density.

## 7. Workflow

```text
Read Need
      ↓
Read Mission Type
      ↓
Get Ganesha Symbols matching best_need_ids and/or best_mission_types
      ↓
Validate symbol_theme against symbolThemes
      ↓
Use Belief / World / Beat Plan / Structure / Opening / Ending as contextual guidance
      ↓
Rank
      ↓
Select Symbol(s)
      ↓
Validate
```

## 8. Rules

SY-001 Symbol must exist in the approved Symbol index.

SY-002 Symbol IDs are Ganesha Symbol IDs from `ontology/ganeshaSymbols.json` (e.g. `GAN_SYM_MOUSE`), not invented generic symbol IDs.

SY-003 Symbol compatibility is limited to the real fields `best_need_ids` and `best_mission_types`.

SY-004 `symbol_theme` must validate against `ontology/symbolThemes.json`.

SY-005 Do not invent direct compatibility fields for Belief, World, Beat Plan, Structure, Opening, or Ending.

SY-006 Belief, World, Beat Plan, Structure, Opening, and Ending may guide selection contextually, but they are not direct Symbol-index compatibility fields in the real source.

SY-007 Preserve `best_need_ids` and `best_mission_types` exactly.

SY-008 Do not invent a symbol timeline or beat linkage.

SY-009 Avoid unnecessary symbol overload.

SY-010 Symbols must not replace actual character growth.

SY-011 Do not determine final illustration composition.

## 9. Validation

Validate:

- Symbol exists.
- Symbol theme is valid.
- Symbol supports the Need and/or Mission Type through real source fields.
- Symbol count is appropriate.
- No symbolic contradiction exists.
- Resolution trace distinguishes source-backed compatibility from contextual guidance.

## 10. Failure Handling

If no appropriate symbol exists:

- Return `SYMBOL_UNRESOLVED`.
- The story may proceed without a symbol if symbols are optional for the selected story type.

If a symbol's `symbol_theme` is not found in `symbolThemes.json`:

- Exclude that symbol as an integrity failure.
- Continue if other valid symbols remain.

If a symbol cannot be integrated cleanly:

- Identify the conflict.
- Do not invent a new generic symbol or hidden beat-linkage layer.
