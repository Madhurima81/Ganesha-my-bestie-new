# Phase 6A.03 - Belief Resolver

Version: 2.0
Status: LOCKED

## 1. Purpose

The Belief Resolver determines the False Belief and True Belief associated with the selected Situation and validates that the belief shift supports the selected Core Need.

A real `ontology/beliefs.json` file does exist in the uploaded bundle, but the reconciled Phase 6A contract still uses the Situation record as the direct source for false/true belief wording. The Belief ontology may be useful for audits or future phases, but it is **not** the primary resolver input for Phase 6A belief wording.

## 5. Resources Used

- `plannerKnowledge.situationIndex`

The resolver reads the false/true belief wording already attached to the selected Situation.

## 6. Responsibilities

- Read False Belief from the selected Situation.
- Read True Belief from the selected Situation.
- Construct the Belief Shift.
- Validate the shift against the selected Core Need.
- Preserve the Situation's source wording.
- Store the belief information in Planner Context.

## 7. Workflow

```text
Read Situation
      ↓
Read false_belief_text
      ↓
Read true_belief_text
      ↓
Build Belief Shift
      ↓
Validate Against Core Need
      ↓
Store in Planner Context
      ↓
Pass to Character Resolver
```

## 8. Rules

BR-001 Do not invent beliefs.

BR-002 False Belief must come from the selected Situation record.

BR-003 True Belief must come from the selected Situation record.

BR-004 False and True Beliefs must represent a meaningful transformation.

BR-005 Belief Shift must support the selected Core Need.

BR-006 Preserve the source belief meaning.

BR-007 Do not normalize beliefs into new planner IDs during Phase 6A.

BR-008 Do not require `ontology/beliefs.json` for the primary wording lookup in Phase 6A, even though that ontology file exists in the uploaded bundle.

## 9. Validation

Validate:

- Situation exists.
- False Belief exists.
- True Belief exists.
- False and True Beliefs are not identical.
- Belief Shift is meaningful.
- Belief Shift supports the Core Need.
- Source Situation is traceable.

## 10. Failure Handling

If either belief is missing:

- Return `BELIEF_UNRESOLVED`.
- Identify the Situation.
- Do not invent replacement wording.

If the belief shift conflicts with the Need:

- Return a validation failure.
- Do not silently replace the Situation's belief data.
